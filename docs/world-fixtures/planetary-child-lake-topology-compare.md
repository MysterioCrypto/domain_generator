# P2-B2.6 — проверка геометрических котловин и Core MFD с/без lake supernodes

**Статус:** внешний, неканонический диагностический инструмент PR #103. [Обоснование и приватный независимый эксперимент B/C](../reviews/p2-b2-6-core-lake-topology-vs-private-bc-2026-11-21.md).

## До запуска

Нужен **не публичный** архив исходной планеты A8/A12, предварительно преобразованный в [macro-region-source.npz](planetary-geogrid-adapter.md) и [child-terrain-generated.npz](planetary-child-terrain.md) с шагом 1 км. Программа принимает **только child NPZ + manifest**, не требует полного старого A8 ZIP и не загружает ваши данные в публичный GitHub.

Из корня локального checkout **PR #103**:

```bash
python scripts/diagnose_planetary_child_lake_topology_v02.py \
  --child-npz /private/child-B/child-terrain-generated.npz \
  --child-manifest /private/child-B/manifest.json \
  --lake-min-area-km2 16 \
  --lake-min-depth-m 10 \
  --max-lake-supernodes 12 \
  --max-total-candidate-cells 12000 \
  --output /private/child-B/core-lake-topology
```

Повторить отдельно для C. **16 км² / 10 м — исследовательские критерии геометрического отбора, не физическая или земная классификация озёр.** Все значения редактируемы.

## Как читать результат

- `lake-topology-review.png`: рельеф, **виртуальное** заполнение для отвода воды, геометрические чаши и точки перелива, изменение локального MFD-накопления при использовании озёрных supernodes.
- `lake-topology-comparison.npz`: два поля накопленной площади с и без lake proxy, маска кандидатов, `lake_comparison_available_mask`. Если сравнение не разрешено, последние данные **не сравнимы**: 0 в декоративном поле разности — НЕ нулевой эффект.
- `manifest.json`: отдельные ledger по суммарной площади на краевых терминалах, статус выбора Core spill, число/площадь кандидатных чаш, максимальная **внутренняя** разница в накопленной площади и возможная смена распределения по граничным выходам.
- Если число чаш превышает 12 или занято более 12 000 candidate cells, возвращается `UNRESOLVED`, без выдуманного правильного перелива.
- Малые чаши проверяются штатной Core nested hierarchy, а для слишком больших иерархий дорогое вычисление пропускается с явной пометкой.

**НЕЛЬЗЯ** читать площади как Q в м³/с, считать виртуальную глубину заполнения реальной глубиной воды или считать каждый геометрический basin постоянным озером. Сравнение выполняется при **нулевом внешнем поступлении A8**, следовательно показывает локальную топологию, не межрегиональный водный баланс.
