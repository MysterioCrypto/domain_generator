# ADR-0004 — Нормативные документы и примеры

## Контекст

При проектировании генератора конкретный пример легко случайно превратить в скрытое правило. Это уже приводило к архитектурному дрейфу в предыдущем эксперименте с battlemap.

## Решение

Документы используют YAML front matter. Ключевые поля: `kind`, `status`, `normative`.

Иллюстративные примеры обязаны иметь `normative: false`. Они проверяют выразительность системы, но сами не создают требований Core.

Существенные архитектурные изменения сначала обсуждаются с владельцем проекта. После согласования обновляется документация/ADR, затем код.

## Следствия

- Пример с фортом, ущельем или конкретной кампанией не может сам по себе породить специальный алгоритм.
- Новый чат может отличить правила от иллюстраций машинно и при чтении Markdown.
- История причин решений хранится в Git, а не только в контексте разговора.
