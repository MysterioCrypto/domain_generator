# ADR-0002 — Разделение DomainSpec, GenerationPlan и DomainData

## Контекст

Пользователь описывает желаемую структуру мира, а процедурный генератор создаёт конкретную геометрию. Если смешать эти уровни, входные пожелания начинают незаметно превращаться в результат, а pipeline становится трудно изменять.

## Решение

Использовать три разные модели:

- `DomainSpec` — намерение, seed и constraints;
- `GenerationPlan` — конкретизированный пространственный план одного запуска;
- `DomainData` — фактически полученный domain.

`DomainSpec` не модифицируется генератором. `GenerationPlan` можно пересоздать. `DomainData` является каноническим результатом.

## Следствия

Можно переписывать layout/elevation/hydrology, не меняя внешний язык требований. Один `DomainSpec` может давать разные допустимые candidates при разных seeds или attempts, а результат остаётся явно отделён от исходного намерения.
