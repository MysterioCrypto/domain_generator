# P4-C1 — внешний макровход A8 ↔ доминантная сеть Core MFD района A (НЕ речной канон)

**Дата:** 2026-11-21. **PR:** #103, DRAFT, UNMERGED. **Принятая ветка:** \`dev/0.2\` не изменялась. **Статус:** неканонический доказательный эксперимент; не принимает ни карты рек, ни водосборы, ни водность. Автор ранее выбрал \`spherical_xyz_v1\` как рабочий рельеф, но это не санкционирует изменение его макрогеографии или утверждение водных объектов.

## Зачем понадобился P4-C1

P4-B нашёл 5 868 кандидатных соседних рёбер, из них 4 517 проходят строгую проверку сырого DEM, ещё 1 351 скрыты. Но P4-B не знает, сколько воды приходит из других частей глобальной планеты и принадлежит ли старый A8/D8 вход новому 1-км MFD-водосбору. **Нельзя умножить макроплощадь на MFD на глаз**, потому что историческая площадь A8 включает неизвестные пересечения, возвращения и не обязана быть площадью *только за пределами вырезки*.

Эта одна ограниченная итерация **не добавляет физику**. Она строит явный «журнал гипотез связности»: обнаруживает старые направленные входы A8 в регион, выбирает только существующие положительно проверенные P4-B рёбра, направленные внутрь региона, отслеживает действующий P2-B2.4 доминантный MFD-граф до края и сравнивает его позицию с известным старым A8-выходом. На каждом шаге сохранено, где модельное совпадение ещё НЕ означает общий водосбор.

## Новый изолированный инструмент

- \`scripts/reconcile_region_boundary_corridors_v02.py\` — CLI и read-only \`reconcile_boundary\`. Ни DEM, ни P3 cover, ни MFD, ни \`DomainData\`, ни авторская спецификация не мутируются.
- \`tests/test_region_boundary_corridors_v02.py\` — **14 синтетических тестов**: положительный внешний вход, неудачное соответствие, нестабильные/дублированные рёбра, цикл, несовпадение старого A8 и записанных A8-выходов P2, отвергнутая подмена child/projection/P4-A через SHA-256, неизменность входов и побайтово одинаковый повтор PNG/JSON.
- В существующем \`non-earth-geogrid-source-adapter-v02.yml\` добавлена проверка сквозного CLI из только **синтетических** A8/A12 → P2 → P4-B → P4-C1. Никаких приватных ZIP и NPZ в GitHub Actions.

Проверяются *точные* SHA-256 дочернего NPZ, проекции P2-B2.4 и P4-A PNG относительно предыдущего P4-B аудита. Повторно воспроизводятся записанные старые макровыходы A8 из того же macro NPZ. Проекционные рёбра P2 = дизъюнктное объединение strict и withheld рёбер P4-B; lake jumps не рисуются как водные линии; при ошибке проверки выполнение прекращается. Старые входные площади никогда не импортируются в MFD автоматически.

**Важная граница:** проверяется целостность уже вычисленного P4-B Core-MFD результата, а не заново выполняется независимая физическая модель стока. Визуальные геометрические пары — не доказательство совпадения гидрологических catchment IDs.

## Реальная приватная Осве́ра, район A

**Источник этой итерации:** уже сохранённый [приватный производный пакет P4-B](https://drive.google.com/file/d/1G6hxsqMNBIk_ZovBZ4nrepf7fLOxrHtX/view). В этом запуске **НЕ загружались заново оригинальные A8/A12 ZIP и НЕ пересчитывались P1/P2/P3**; используются хешированные производные массивы P4-B, идентифицированные его исходными SHA-256:

- original A8 \`6824ccf2a4aea7b2514a4e694e84ad13fd3ff4e18dba6c3be6b4b7753dc019ec\`
- original A12 \`db9f0f91fca845058c658dfdd639c882b9cf0514736b3677184a4c84ff20b3a4\`
- размер 231×231, 1 км, \`spherical_xyz_v1\`, 63 сохранённых исходных высотных опоры и 0 м ошибки (проверено в P4-B upstream).
- этот P4-C1 исходник: Git blob SHA-1 \`c945ded2eb31d8fd512dd2515cec3b45d4a564ab\`; одноимённый файл в рабочей ветке сверён с локальным исполняемым.

**Один старый макровход A8** на востоке близ юго-восточного угла: координата пересечения (east=+115 км, north≈−110.083 км). Указанная в исторической A8 накопленная площадь ≈86 107 км² — **опасная подсказка, НЕ внешний-only водосбор; 0 км² автоматически добавлено**.

В окне 30 км найдено 20 строгих «направленных внутрь» рёбер P4-B. Они принадлежат маршрутам, которые сходятся в **одной** дочерней конечной ячейке ([row=209, col=0], западная граница). Выбранный ближайший внутренний старт [row=220, col=224] удалён от старого входа на ≈7.864 км. Путь доминантной MFD-проекции: 253 ребра, из них **181 strict/raw-downhill** и **72 withheld** (недостаточная геометрическая достоверность). Это **не 253 км доказанной реки** и не физически непрерывный водоток.

**Один старый макровыход A8** на западе (north≈−96.028 км). Конечная ячейка дочернего графа north=−94 км находится от старого выхода на ≈2.028 км. Старый A8 hint upstream area при выходе ≈315 647 км² **не означает** действительную площадь нового MFD и не используется.

Ноль proxy-переходов при текущем пороге \`NO_LAKES_QUALIFIED\` — не доказательство отсутствия озёр; 1 374 ячейки P4-B virtual fill >2 м остаются риском. Правка 72 небезопасных переходов намеренно **не выполнялась**: нет подтверждения, что в них действительно должны проходить русла.

**Изображение:** охристые линии только там, где ребро прошло strict P4-B; пурпурные точки на withheld edges — не вода; треугольник — исходный A8 вход с позиционной неопределённостью, а не утверждённая точка русла. Не сглаживать диагональный путь до подтверждения физики.
