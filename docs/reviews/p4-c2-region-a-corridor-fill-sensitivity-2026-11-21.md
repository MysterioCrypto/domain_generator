# P4-C2 — устойчивость MFD-коридора к виртуальному заполнению и исходным подъёмам (НЕ РЕКИ)

**Дата:** 2026-11-21. **Статус:** диагностическая рабочая гипотеза, не каноническая география. **PR:** #103 (Draft / Unmerged), `dev/0.2` и замороженный release не менялись.

## Зачем

P4-C1 выявил один геометрически согласованный ориентировочный путь от исторического входа A8 на востоке к MFD-терминалу на западе (253 ребра). На 72 рёбрах строгая пригодность исходного DEM не доказана. Следующая необходимая задача — различить **собственные подъёмы raw DEM** и **зависимость классификации от виртуального Priority Flood заполнения**, а не произвольно «докрасить» маршрут водой или подогнать elevation. Нет данных для изобретения внешнего притока.

## Выполненный ограниченный slice

Добавлен **`scripts/audit_region_corridor_sensitivity_v02.py`** — read-only CLI поверх уже вычисленных P4-A, P4-B и P4-C1, без нового Core-routing, без мутации оригинальных NPZ, без расхода Q, без отнесения впадин к озёрам. Принудительно проверяет SHA-256 источников относительно P4-C1 аудита; заново воспроизводит P4-C1 маршрут, сравнивает его с сохранёнными route summaries и P4-B partition. Проверяемая численная величина каждой пары: `delta_raw_z = z_receiver - z_source` и `max(virtual_fill[source], virtual_fill[receiver])`.

Для каждого ребра сохраняется отдельный признак:
- **strict**: `delta_raw_z < 0` и оба конца не выше порога заполнения;
- **raw_uphill_or_flat**: `delta_raw_z >= 0` (само по себе не может стать «допустимой рекой» от увеличения порога);
- **virtual_fill_over_baseline**: только математический fill-depth >2 м; **НЕ** физическая глубина;
- **both**: оба основания для отклонения;
- **proxy**: условный геометрический lake jump, никогда не трактуется как реальная вода.

Отдельные маски уровня P4-B, Core MFD, маска леса и DEM остаются исходными. Сценарный порог меняет **только диагностическую eligibility classification**, а не маршрутизатор и не исходную геометрию.

`tests/test_region_corridor_sensitivity_v02.py`: **17 локальных синтетических тестов** (истинный raw uphill, виртуальное заполнение отдельно, пересечение причин, отказ по некорректной lineage/baseline, разделение proxy и воды, отсутствие маршрута, replay input immutability и детерминированное построение PNG). Дополнительно существующий географический GitHub Actions workflow выполняет P4-C2 CLI на **синтетических** исходных данных, из того же набора что P4-C1, и проверяет сценарии и запрет подстановки внешней площади.

## Реальная приватная проверка района A

Использован **существующий хешированный частный P4-B derived ZIP** из Drive (его происхождение A8/A12 было проверено в P4-B); повторно загружать исходные большие A8/A12 не требовалось. P4-C1 audit воспроизведён из тех же производных данных с точными SHA-256.

| Показатель на выбранном P4-C1 пути | Результат |
| --- | ---: |
| Всего рёбер доминантной *модельной* MFD-проекции | 253 |
| Baseline порог Priority Flood | 2 м |
| Strict raw-downhill & <=2 м fill | **181** |
| Только raw-uphill/flat | **49** |
| Только >2 м virtual fill | **14** |
| Одновременно raw-uphill/flat и >2 м fill | **9** |
| Число неустранимых увеличением порога fill неблагоприятных raw-gradient рёбер | **58** |
| Максимальная серия подряд идущих strict-рёбер при 2 м | **30** |
| Геометрических lake proxy в выбранном пути | 0 |
| Внешняя площадь автоматически инжектирована | **0 км²** |

Чувствительность **к визуальному порогу (не к реальной воде)**:

| Порог виртуального заполнения | Strict | Withheld | Самая длинная consecutive strict серия |
| ---: | ---: | ---: | ---: |
| 0 м | 128 | 125 | 28 |
| 1 м | 161 | 92 | 29 |
| **2 м** | **181** | **72** | **30** |
| 3 м | 185 | 68 | 31 |
| 5 м | 189 | 64 | 32 |
| 10 м | 195 | 58 | 33 |

**Интерпретация:** 14 исходно withheld рёбер чувствительны только к порогу заполнения; 58 имеют неблагоприятный сырой уклон и принципиально остаются невалидированными без новых данных / отдельного геоморфологического контракта. При 10 м разрешены 195 рёбер лишь для display-eligibility, но raw-gradient ограничение остаётся. Нет основания автоматически создать 253 последовательных физических русловых звена, озёра или изменять рельеф.

Не установлен физический runoff, baseflow, water permanence, basin identity между старым A8/D8 и новым MFD, groundwater, эффект catchment residence/storage. Историческая A8 upstream площадь **НЕ** является измеренным «внешним only» водосбором; диапазон внешнего inflow сейчас **не ограничен** наблюдениями. Не подставлять A8 cumulative из старого D8 в новый MFD.

## Следующий ограниченный этап

**P4-D / качественная география:** сначала определиться, надо ли изменять *реальные входные данные ландшафта* в пользу узнаваемой карты или использовать отдельную честную условную географическую трактовку. 58 raw-uphill рёбер сами по себе **не доказывают ошибку генератора**: возможно, старый макроводоток A8 и новая дочерняя MFD сеть имеют разные бассейны, либо необходима специально заданная переработка рельефа с сохранением исходных якорей. Следующий шаг — проверить **topographic anchoring и локальную концентрацию подъёмов**, не приступать к массовой правке DEM, не «принять» карту автоматически и не сливать #103.
