# P4-G — масштаб отображения модельных русловых скелетов, 3×3 sensitivity (НЕ канонические реки)

**Дата:** 2026-11-21. **Статус:** PRIVATE derived / read-only / noncanonical. **PR #103:** Draft, не слит. **Принятый Core `dev/0.2`:** без изменений.

## Проблема

После P4-F три варианта `relief_strength={0.5,1.25,2.0}` имеют собственные MFD-совместимые модельные сети, но даже лучшая математическая локальная связность не означает картографически красивый регион. Историческая пользовательская оценка карты региона: прежние эскизы не воспринимались полноценной географической картой. Поэтому приоритет — **видимый продукт и читаемость**, не гипотетическое увеличение точности физики без зрительного эффекта.

В этом шаге исследуется единственная независимая ось, **порог выделения тонкого model channel skeleton**, при фиксированном DEM каждого варианта. `stream_threshold_km2={15,30,60}` (км² модели, **не Q, не м³/с**). Всего 9 комбинаций. Никаких новых seed, изменённого parent interpolation, автоматического A8 стока и подтверждённых river mouths.

## Выполненная проверка

Новый read-only модуль `scripts/compare_region_channel_scale_v02.py`:

- Проверяет SHA-256 исходных P4-F/P4-E baseline macro, DEM, вариантов NPZ, P4-E JSON и archived P2-B2.4 reference.
- **Заново** вызывает штатный `connected_mfd_channel_projection` для каждого из девяти случаев. При `threshold=30` весь output raster/edge/proxy пересчитан и побитово совпадает с сохранёнными тремя projection NPZ P4-F. Не допускается молчаливая перерисовка прежнего графа.
- Контролирует conservation float64 ledger, нулевую автоматическую подкачку внешней A8 площади, корректность adjacent ordinary edges, независимость source/receiver и соответствие ledger.
- Замеряет model-edge length в километрах (диагонали учитываются как √2), количество topological tips / confluences, долю диагональных рёбер, mask IoU, новые и потерянные ячейки относительно baseline 30.
- Строит две **отдельные** карты из старых P4-E картографических фонов с frozen P3 candidate colors: тройное сравнение при пороге 30 и матрицу 3×3 одинакового масштаба. Линии раскрашены и утолщены по **модельной unique dominant-channel area**, это **не реальная ширина русла/расход**.
- 17 синтетических тестов: toy Core 3×3 crossings, полный deterministic CLI replay и SHA guards, запрет смены parent DEM/land grid, повреждённые графы, несогласованные threshold/ledger, фиксированная визуализация.

## Численные результаты на PRIVATE районе A, 231×231 км²-пикселя

Числа ниже — ordinary model-channel cells и **число model-слияний**, где минимум два ordinary upstream edges входят в один ordinary node (не реальные confluences).

| Рельеф | 15 км²: cells / joins | 30 км² | 60 км² |
|---|---:|---:|---:|
| **0.5** | **15 083 / 1 123** | **9 117 / 528** | **6 004 / 239** |
| **1.25** | **9 354 / 968** | **6 394 / 449** | **4 538 / 211** |
| **2.0** | **8 513 / 927** | **5 893 / 442** | **4 248 / 218** |

- При `threshold=30` суммарная геометрическая длина model adjacent edges, включая диагонали: **11 018 / 7 465 / 6 788 км** соответственно (0.5/1.25/2.0). Это длина *распределённой сетевой геометрии*, не длина подтверждённой реки и не trunk length.
- Доли диагональных ordinary edges при 30 км²: **51.1% / 41.3% / 37.9%**. Это не достаточная самостоятельная мера grid-lock, но в сочетании с видимыми длинными одинаково ориентированными отрезками — дополнительный красный флаг.
- Граничных модельных channel endpoints для исходного порога 30 км²: **22 / 20 / 25**; они воспроизведены без изменений относительно P4-F.
- При повышении порога с 30 до 60 происходит не только удаление, но и **появление новых пикселей** model channel относительно прежней маски: **466 / 131 / 101**. Это закономерно: `receiver_preference` внутри 1D projection зависит от порога и может выбирать другой downstream pixel при НЕИЗМЕННОМ распределении Core MFD fractions. Маски **не строго вложенные**, и запрещено писать renderer как простое скрытие младших ветвей предыдущего результата.
- Пересечение IoU по рельефам 1.25 и 2.0 (при порогах 15/30/60): **46.27% / 40.44% / 34.92%**. Повышение порога само по себе не сближает различающиеся схемы рельефа.

Все сравнения сохраняют исходные 63 parent height anchors унаследованных P4-E DEM и локальную площадь 53 361 км². Из старого A8 не подставляется ни один км² outside-only catchment.

## Визуальная оценка — важная отрицательная находка

**Значимый недостаток не устранён.** При `relief_strength=0.5` видны искусственно **длинные параллельные диагональные и горизонтальные сегменты**, особенно в восточной половине карты; форма не выглядит зрелой естественной дендритной сетью. Варианты 1.25 и 2.0 дают более фрагментированные/нерегулярные узоры, но заметная клеточная и ступенчатая структура остаётся и у них.

Переход 15→60 уменьшает плотность и загруженность картинки, но **не исправляет топологию/искусственную направленность**. Условный синий цвет не является доказательством воды. Изображение по-прежнему не следует объявлять законченной региональной картой: в нём нет проверенной гидрографии, населённых пунктов, дорог, авторских локаций, подписей и картографической иерархии.

**Инженерная оценка:** нельзя автоматически выбрать 0.5 только потому, что P4-E показал меньше raw DEM uphill на старом коридоре. Нужны причинные измерения ориентационного смещения, структурных долин и передачи масштаба родительских A8 высот, прежде чем выбирать рельеф или отправлять геометрию в ImageGen. Приоритет — читаемая карта для НРИ/литературы, а не «улучшить число тестов».
