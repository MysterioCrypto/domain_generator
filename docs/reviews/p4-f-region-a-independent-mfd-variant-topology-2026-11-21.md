# P4-F — три независимо пересчитанные Core-MFD топологии на вариантах рельефа A (НЕ реки)

**Дата:** 2026-11-21. **Статус:** PRIVATE noncanonical model evidence. **PR:** #103 Draft/Open/Unmerged; принятые `dev/0.2` и frozen release не изменены. Пользователь не принимал конкретный новый вариант рельефа/рек.

## Почему это нужно

P4-E показал, что снижение `relief_strength` с 2.0 до 0.5 уменьшает число локальных геометрических «подъёмов» на **старом, фиксированном** 253-звенном P4-C1 пути с 58 до 15. Но старый receiver/path принадлежит **старому рельефу**. Более гладкий DEM может перенаправить *новый* MFD в другой сток. P4-F впервые **самостоятельно** пересчитывает модель на **каждой** новой поверхности вместо наложения старой реки.

**Архитектурный контракт:** Core 0.2 `priority_flood_surfaces` + `continuous_routing_field` + проверяемый `P2-B2.4 connected_mfd_channel_projection`; model dominant 1-receiver graph определяется из новой Core MFD, а fractional accumulation остаётся отдельной величиной. Ни A8 D8, ни image renderer не имеют права менять новую сеть. Условные lake proxies не называются водой.

## Выполненный один bounded slice

- Добавлен read-only CLI `scripts/compare_region_mfd_variant_basins_v02.py`: принимает P4-B baseline source+P2 NPZ, хешированную P4-C1 reference inlet, SHA-проверенные P4-E новые NPZ для 0.5/1.25 и три исходных P4-E PNG. Каждый вариант **независимо** проходит существующий Core-compatible routing/projection. Любое несоответствие SHA-256 P4-C1/P4-E, размеров, исходных parent anchors, coastline/land-mask либо baseline projection прекращает выполнение.
- Baseline 2.0 **заново пересчитан ПОБИТОВО идентично** сохранённому P2-B2.4 NPZ (все модельные поля) и **точно** воспроизведён старый JSON-отчёт; проверены исходные маршруты и P4-C1 восточный старт.
- Для каждой ячейки найдена **модельная** конечная граничная ячейка доминантного графа, проверены циклы, неизвестные nonlocal переходы и преждевременная остановка; для каждой новой поверхности сравниваются абсолютная идентичность конечного пикселя, сторона выхода, пересечение channel-mask IoU и по сторонам сумма **fractional** MFD contributing area.
- Все три вычисления имеют исходный **локальный** объём модельной площади 53 361 км², и сохранение площади на границах с численной ошибкой порядка 1e-10 км². **Автоматический внешний A8-поток равен 0 км²**, физический Q, recharge и river permanence не моделируются.
- Варианты сохраняют **63 source parent height stations, parent interpolation и 231×231 grid**, land mask не изменяется. P3 cover *не пересчитывается*: верхняя раскраска из P4-E лишь стабильный фон для просмотра.
- `tests/test_region_mfd_variant_basins_v02.py`: **24 синтетических теста**, в том числе реальный routing Core на малом искусственном DEM, exact baseline replay, проверка SHA/повторного CLI, защита против неверного C1 inlet/area и MFD-провалов, графовые циклы/нелокальные переходы/терминация, бухгалтерия boundary side, детерминированный PNG. Синтетический geogrid CI запускает P4-F после P4-E, когда synthetic region содержит нужный C1 коридор; иначе полный positive toy CLI остаётся обязательным.

## Реальный район A — численные результаты

Порог для построения *модельного* руслового скелета одинаковый: **30 км² (не Q)**. Оригинальный A8 вход остаётся только позиционной гипотезой, не установленной рекой.

| Параметр | 0.5 (приглушённая деталь) | 1.25 (умеренная) | 2.0 (исходный) |
|---|---:|---:|---:|
| Соединённых модельных channel terminal pixels | **22** | **20** | **25** |
| Ячеек thin dominant channel skeleton | **9 117** | **6 394** | **5 893** |
| Ordinary adjacent skeleton edges | **9 095** | **6 374** | **5 868** |
| IoU масок канала относительно 2.0 | **18.47%** | **40.44%** | **100%** |
| Доля ячеек с **тем же точным граничным пикселем** доминантного выхода относительно 2.0 | **52.72%** | **85.96%** | **100%** |
| Доля ячеек с **той же стороной границы** относительно 2.0 | **94.88%** | **95.67%** | **100%** |
| Историческая P4-C1 пробная точка [row=220,col=224] приводит к терминалу | **[177,0] запад** | **[209,0] запад** | **[209,0] запад** |
| Geometric lake proxy jumps в выбранной сети | 0 | 0 | 0 |
| Внешняя площадь, заимствованная из старого A8/D8 | **0 км²** | **0 км²** | **0 км²** |

IoU между **самими** альтернативами 0.5 и 1.25: **24.18%**. Положение выхода пробы 0.5 изменилось **на 32 км вдоль западной кромки**, по сравнению со старым [209,0]; это не подтверждает ни правильность нового выхода, ни достоверность старой A8 гидрографии.

**Fractional MFD** (не 1-receiver) модельная площадь, пришедшая к *стороне* локальной вырезки, км²:

| Сторона | 0.5 | 1.25 | 2.0 |
|---|---:|---:|---:|
| Запад | 51 790.13 | 51 417.58 | 49 027.01 |
| Юг | 496.65 | 783.89 | 2 683.10 |
| Север | 828.30 | 861.99 | 875.87 |
| Восток | 245.91 | 297.54 | 775.02 |
| Сумма | **≈53 361** | **≈53 361** | **≈53 361** |

**Важнейшее различие:** уникальный «dominant terminal pixel» — свойство отобранного single-receiver канального скелета. Исходный **MFD** распределяет массу *дробно* между всеми допустимыми соседями; поэтому ни единичные dominant root IDs, ни совпадение стороны выхода **НЕ являются** физическими водосборными ID или discharge. Историческая A8 catchment площадь ~86k км² при входе сюда не подставлялась: она не измеренная external-only площадь.

## Визуальное сравнение

Верхний ряд: **три заново рассчитанных модельных русловых скелета**, подписанные model-only, на прежнем P4-E картографическом фоне (не «вода»); пять наибольших терминалов отмечены оранжевыми точками, выбранный исторический источник — светлая отметка. Нижний ряд: original 2.0 — стороны доминантного выхода (четыре цвета); 0.5 и 1.25 — какие клетки сохраняют точный исходный граничный пиксель (зелёный), перенаправлены на другой пиксель той же стороны (охра) или на другую сторону региона (красный).

Рисунок не является представлением канонической гидрографии; нельзя превратить тонкую синюю линию на картинке в доказанный continuous river.

## Следующая ограниченная итерация — P4-G

Проверить **картографическую форму** заново рассчитанных model channel skeletons на разном пороге и чувствительность к source-cell choice/количеству ветвей, без расстановки реальных рек, settlements, POI или автоматической «приёмки» нового DEM. Составить author-visible региональную карту, приближающуюся к ожидаемому масштабу, прежде чем выносить вопрос о выборе `relief_strength`. Не вводить новую физику без измеримой пользы для карты.
