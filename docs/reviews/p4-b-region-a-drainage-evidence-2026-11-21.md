# P4-B — консервативная дренажная связность района A на настоящих исходниках (НЕ реки)

**Дата:** 2026-11-21. **Ветка:** draft PR #103, не слит с \`dev/0.2\`; принятый Core и freeze неизменны. **Статус географии:** P4_B_NONCANONICAL_DRAINAGE_EVIDENCE / НЕ авторский канон / НЕ физическая водная сеть / без визуальной приёмки этой новой карты.

## Зачем понадобился P4-B

P4-A создаёт картографическую подложку, но не имеет ни одной доказанной линии рек, озёр и маршрутов. Ранее P2-B2.4 уже дал **связный доминантный граф** из принятых Core 0.2 Priority Flood + MFD, а не новую гидрологию. Однако:
- MFD \`contributing_area\` = площадь водосбора, **не** расход или наличие постоянной воды;
- Core dominant-channel skeleton — одноприёмниковая проекция для карты, **не** вся 1D RiverNetwork;
- при Priority Flood часть областей виртуально заполнена, что может образовывать фиктивный переход через впадину;
- lake proxy transitions не являются надводными каналами;
- upstream источники за границей crop не согласованы с исходным глобальным A8; близость D8 и MFD выходов не доказывает единства водосборов;
- P2-B2.5 уже опроверг попытку «починить» реку произвольным углублением DEM.

**Решение:** сделать только отдельный P4-B evidence layer на существующей P4-A, **без изменения DEM, MFD, растительности, Core, A8 или авторского ledger**. Выявлять сомнительные сегменты раньше, чем рисовать «настоящую речную» карту.

## Реализация

Новый \`scripts/render_region_drainage_evidence_v02.py\` принимает:
- P2 child NPZ и неканонический manifest;
- отдельный P2-B2.4 \`connected-MFD-channel-reference.npz\` и \`manifest.json\`;
- чистый P4-A PNG и его JSON-аудит.

CLI **обязательно сверяет SHA-256 исходного дочернего NPZ с хешем, зафиксированным в P4-A**, прежде чем накладывать другую географию на карту. Это предотвращает тихое наложение топологии другого региона того же размера. Битовая привязка самого P2-B2.4 projection NPZ к child **не доказана SHA**: дополнительно заново вычисляются принятые Core Priority Flood/MFD и для каждого рисуемого сегмента проверяются: ровно один следующий узел, соседство Moore, положительная доля MFD, строгий спад routing DEM. Уровень исходного DEM обязан **уменьшаться**, а виртуальное заполнение в обеих конечных ячейках не может превышать установленный явно порог.

Все lake proxy jumps и не прошедшие raw-DEM/virtual-fill сегменты исключены из линий. Они не дорисовываются и не сглаживаются искусственно. Неопределённые области — фиолетовые **сигналы риска, не вода**. Валидные сегменты — охристые **кандидаты стоковых коридоров, не подтверждённые реки**. Граф фиксированной 1-км сетки выглядит угловатым и ещё НЕ является world-space сглаженной речной геометрией.

Добавлен **отдельный масштабный дисплейный** параметр \`--min-display-dominant-area-km2\` (дефолт 0, чтобы ничего не терять). Он фильтрует лишь линии на изображении; полная проверенная геометрия всегда сохраняется в NPZ. \`--virtual-fill-limit-m\` по умолчанию равен 2 м и отражает **осторожный критерий визуальной неопределённости, не физический уровень водного зеркала**.

Выход: \`drainage-evidence-map.png\`, \`drainage-evidence-sheet.png\`, \`drainage-evidence-masks.npz\`, \`drainage-evidence-audit.json\`; в JSON сохранены раздельные причины скрытия, входные SHA и признак неопределённого внешнего притока. Плотные мелкие каналы не исчезают из данных.

## Следующий bounded gate

**P4-C — согласование граничных водосборов и озёрных переливов/источников на одном связном графе**, с проверкой реальной географической логики относительно макро A8 без возврата к старому D8 как авторитету. Пока external crop inflow отсутствует и 1 351 геометрических рёбер отклонены, никакая «синяя речная карта» не утверждается. Результат P4-B полезен **как карта географических неопределённостей и топологических подсказок**, но не как готовая карта литературного региона.
