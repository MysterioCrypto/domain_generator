# P2-B2.1 — исходные котловины, геометрические кандидаты и возможные переливы

**2026-11-20.** Исследовательская реализация — [draft PR #103](https://github.com/MysterioCrypto/domain_generator/pull/103). Нормативный Core 0.2 не изменён. Не принимать геометрическое озеро за утверждённый водоём.

## Причина этапа

P2-B1 на источнике A/B/C обнаружил большие регионы виртуального заполнения Priority-Flood. На карте речных линий MFD поверх таких областей могут появляться ложные веера. Перед формированием новой локальной сети необходимо отличать (1) небольшие топологические ямы, (2) геометрически значимые замкнутые чаши и (3) **фактические озёра**, существование которых зависит от воды, сезонности, испарения и авторского мира.

## Что изменено

- `scripts/audit_planetary_child_lakes_v02.py`: **внешний read-only этап** после P2-A, принимающий child NPZ+manifest. Запрещает молчаливую обработку морских пикселей и неравномерной сетки.
- Вызывает **существующие неизменённые** Core функции `priority_flood_surfaces`, `extract_lake_candidates`, `continuous_routing_field`, `choose_lake_outlets`, а на маленькой тестовой сетке `distributed_flow_accumulation_km2` с настоящими lake supernodes. Для небольших чаш использует `build_nested_depression_hierarchy`, но не начинает дорогое расплетение огромных деревьев.
- Экспортирует `required_fill_depth_m`, `provisional_lake_basin_id`, `nonqualified_fill_mask`; структурный отчёт содержит площадь, максимальную **виртуальную** глубину, объём **до уровня перелива (proxy)**, известность точки перелива, ограничения и ограниченный тест сохранения водосборной площади.
- Два явно настраиваемых сценария для демонстрации: минимум 4 км²/2 м и строгий 16 км²/10 м. **Ни один не становится универсальным значением планеты**, ни один не подразумевает заполненность водой. Строгие структурные кандидаты не появляются вне мягкого списка на том же DEM.

Включена проверка матрицы кандидатов при изменении порога.
- На известной 21×21 тестовой котловине обнаруживается одна геометрическая чаша, Core подбирает точку перелива, а **реальный штатный lake-supernode граф** сохраняет исходную площадь до границ с ошибкой меньше 10⁻⁸ км². Полная штатная супернода не запускается на большой дочерней сетке: нет оснований выдавать безозёрную быструю аккумуляцию за правильную lake routing.
- Фокусные тесты: 27 passed (19 старых и 8 новых). Полный pytest на алгоритмическом коммите: 532 passed. Для итогового документационного коммита нужна повторная CI-проверка.

Регион A/B/C и численные диагностические файлы оставлены **в чате**, не загружены в публичный репозиторий. В этом скрининге использован **другой** C2-сплайн, а не точный C1 Hermite сценарий P2-A, поэтому результаты не являются побайтово воспроизводимой регрессией PR #103 и не служат абсолютным количеством озёр.
- Ни приватные архивы, ни производные приватные карты в GitHub Actions не размещались.

## Инварианты, которые ещё НЕ обеспечены

1. Кандидат при достаточной площади и глубине **не означает**, что водосбор предоставляет воду в объёме, достаточном для постоянного озера. `virtual fill` — не фактическая глубина.
2. Выбор возможного Core spill — **не** проверка стока в планетарный год, заполнения водоёма и не гарантия единственного физического реального выхода.
3. На реальном 231×231 регионе Core lake supernode accumulation целиком **ещё не запускалась** (избегаем ошибки и затрат большого O(N²) Python-алгоритма). Внешние макропритоки и сходство с A8 D8 ещё не внесены.
4. Если структурных кандидатов больше установленного лимита или Core не может найти ацикличную точку перелива, отчёт сохраняет **unresolved** вместо подстановки удобного выхода.
5. Нет утверждённых координат водопада, реальной экологии, дороги, города, постоянства рек и магических источников воды.

## Следующий ограниченный шаг — P2-B2.2

Не рисовать все структурные бассейны синими озёрами. Сначала согласовать наиболее крупные *внутриматериковые* бассейны с макровыходами/входами A8 и внешними водосборными площадями. Затем делать ограниченный **source-conditioned MFD + lake supernodes** на дочерней сетке и сравнивать маршруты с геометрическим масштабом старой планеты. Чтобы отбирать настоящие водоёмы, в перспективе использовать внешний world-specific water-profile, а не скрытый земной закон. Сохранить возможность явного авторского вмешательства.
