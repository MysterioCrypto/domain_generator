# P4-E — три контролируемых режима детализации рельефа района A (НЕ канон)

**Дата:** 2026-11-21. **PR #103:** Draft / Open / Unmerged. **Принятый Core:** `dev/0.2` не изменялся. **Источник:** сохранённые приватные derived P4-B/P4-D; оригинальные A8/A12 не загружались повторно и не публиковались. Статус результата — **альтернативная модель рельефа**, а не установленная география/действующая речная сеть.

## Почему выбран именно P4-E

P4-D выявил 58 неприемлемых raw DEM перепадов вдоль *старой фиксированной* 253-реберной модельной MFD-проекции. В 56 случаях parent interpolation имела нисходящий градиент, который процедура мелкомасштабной детализации обращала. Это обосновывает эксперимент **только с амплитудой локальной детали**, без переписывания макропланеты и без рисования «готовой реки».

Исходный регион A: 231×231 узел при шаге 1 км, 230×230 км, географический режим `spherical_xyz_v1`, seed=1406, **исходная реальная recipe `relief_strength=2.0`**, 63 непрерывных географических height-anchor станции с ошибкой 0 м. Принятый глобальный parent DEM по-прежнему источник опор.

**Три варианта в одном контролируемом сравнении:** `0.5` (приглушённая микротекстура), `1.25` (промежуточная) и `2.0` (точное повторение предыдущего результата). При сравнении **не менялись** A8 source DEM, координатная схема, семя, размер/разрешение, родительская интерполяция, original land mask и 63 source heights.

## Что технически сделано

Добавлен read-only `scripts/compare_region_relief_strength_v02.py`. Он **заново вызывает исходную `generate_child(..., ChildTerrainSettings(relief_strength=...))`**, а не просто интерполирует две готовые картинки. Проверяет точный SHA-256 P4-D source macro/child/manifest и P4-A cover/child; заново вычисляет исходные raw z-разности каждого записанного P4-D звена. Если исходная recipe `2.0` не воспроизводит все 5 сохранённых raster arrays **побитово**, команда не продолжает работу. Для каждого варианта генератор самостоятельно контролирует continuous source stations с точностью не хуже 1e−6 м; parent baseline и land mask обязаны оставаться побитово одинаковыми.

Сравнивается raw DEM знак перепада **только на ранее выбранном неизменном 253-реберном пути P4-D**. Наличие «спуска» означает только `z_target < z_source` — это не проверка того, что *новый* MFD согласится с этим направлением, и не доказательство речного бассейна. Изменение высот в другом месте может вызвать новые водосборы/отклонения — именно поэтому отдельный пересчёт MFD остаётся необходимым.

Подсчитываются математические локальные минимумы внутренней части всей исходной DEM по восьмисоседнему критерию. Это геометрическая диагностика **НЕ озёра**, не заполненный водосбор, не влажность, не runoff.

**Визуальный A/B/C:** верхний ряд 3× map-first P4-A с **одинаковой замороженной P3-кандидатной раскраской**; высоты/освещение и DEM-изолинии меняются. P3 cover **НЕ пересчитан** и для альтернатив может оказаться некорректным. Нижний ряд — подписанные отличия `child_z − parent_interpolated_z`, с одной фиксированной шкалой ±35 м (бирюзовый — ниже, коричневый — выше). Это не гидрологические объекты.

## Сравнение на приватном районе A

| Диагностика | 0.5 (сглаженный) | 1.25 (средний) | 2.0 (baseline) |
| --- | ---: | ---: | ---: |
| Родительских height anchors, точная проверка | 63 | 63 | 63 |
| Максимальная ошибка станций, м | **0** | **0** | **0** |
| Побитовое воспроизведение исходного P4-B child | не применимо | не применимо | **ДА** |
| Raw uphill/flat edges **того же** 253-реберного reference | **15** | **32** | **58** |
| Изначально проблемных 58, ставших downhill | **50** | 28 | 0 |
| Изначально downhill, ставших uphill | **7** | 2 | 0 |
| Математических raw local minima во внутренней 229×229 части DEM | **35** | 307 | 476 |
| Std(child − parent), м | 1.869 | 4.674 | 7.478 |
| Размер land pixels | 53 361 | 53 361 | 53 361 |

**Важное замечание о 15:** при пониженной детализации исправлены 50 прежних переходов, но 7 ранее нисходящих рёбер перестали соответствовать этому признаку. Поэтому `58−50+7=15`. Нельзя заявлять «восстановлена вся река», поскольку это *фиксированный baseline route*, а не новый оптимизированный Core MFD.

**Вывод:** меньшая детализация ощутимо уменьшает raw local pits и препятствия на выбранном модельном пути, не ломая 63 source anchors. Однако это *не доказывает* лучшую художественную карту; при `0.5` часть необходимых малых долин/систем рельефа может стать слишком плоской. `1.25` — компромиссная экспериментальная середина, а не рекомендованное каноническое значение. Автор ещё не выбирал вариант.

## Следующий ограниченный шаг (P4-F)

Сравнить **новые MFD-графы** для `0.5` и `1.25` с baseline `2.0`: количество терминалов, смены принадлежности водосбора, устойчивость структуры руслового скелета и качество видимых географических коридоров, используя тот же старый A8 вход лишь как внешнюю гипотезу. Установить объективные ограничения до выбора нового рельефа. Поддерживать `0 км²` автоматического внешнего притока, не создавать физические реки, не сливать PR #103 без отдельного gate.
